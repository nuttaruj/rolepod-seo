# Decisions — how the scaffold resolved the brief's open items

The design brief lives outside git. These are the choices made during the
scaffold that later sessions need; the reasoning is short on purpose.

| # | Item | Decision | Why |
|---|---|---|---|
| O1 | Rendered `plugins/` tree | Yes — `plugins/rolepod-seo/` is a real copy of `skills/` + the Claude and Codex `plugin.json`, produced by `make render`; `tests/static/parity.sh` fails on drift | Same shape as rolepod-uiproof / rolepod-wplab (marketplaces point at `./plugins/<name>`); a copy survives every CLI's checkout, a symlink does not |
| O2 | JSON sidecar schema v1 | `docs/report-schema.md` for consumers, `skills/seo-audit/references/report.md` § 3 for the model; additive-only; `tests/static/report-schema.sh` checks every documented field appears in the skill copy and validates `tests/fixtures/sample-report.json` | One shape, two audiences; the test is the anti-drift |
| O3 | AI-bot robots policy | Reported as a decision with three options (open / block training only / block all) in `geo-checks.md`; `severity: info`, `owner: human` in the sidecar; an accidental `Disallow: /` under `*` stays an SEO critical | Owner's call, never a defect (brief 02) |
| O4 | `schema-minimums.md` sharing | Single source in `seo-schema/references/`; `seo-audit/references/seo-checks.md` carries a compact required-properties table and a cross-skill pointer; `validate.py` embeds the Required column and `tests/static/schema-minimums.sh` pins doc ↔ script | No symlink, no duplicate long file; the ≤5-files cap holds on both skills |
| O5 | Fixture site | `tests/fixtures/site-a` — fictional plumber, nine pages, `__BASE__` substituted at serve time; defects listed in its README (cross-domain canonical, FAQ without schema, noindex in sitemap, 404 in sitemap, blocked AI bots, duplicate description, two H1s, missing alt) | Every defect is something the collector must surface; golden tables pin the output |
| — | Tooling | bash + python3 only; no Node, no npm, no `package.json` | Skills-only plugin installs from GitHub on every CLI; Python stdlib is the one runtime every target has |
| — | Collector as a shipped script | `skills/seo-audit/scripts/collect.py` is part of the skill, not just a test helper | Makes Tier A deterministic and cheap on every CLI; a scout runs one command and returns a table |
| — | Supporting-file cap vs scripts | `tests/static/skills.sh` counts markdown supporting files (≤5) and `scripts/` files (≤3) separately | The parent's cap protects the context window; scripts are executed, never loaded, so they do not compete for it |
| — | Visual tier (0.3.0) | HTML report rendered from the JSON sidecar by a stdlib script; the same file in `--artifact` form is the Claude Code Artifact; chat matrix carries colored priority dots | Owner asked for the reference's visual outputs (score cards, colored matrix); a renderer over the sidecar keeps one source of truth and no heavy dependency |
| — | PDF (revised 2026-09-04) | No docx, no PDF library, no LibreOffice. `export_pdf.py` uses the print engine of a Chromium-family browser already installed (Chrome / Chromium / Edge / Brave / rolepod-uiproof's Chromium) via `--headless=new --print-to-pdf` — the same page the user would print, fonts embedded; the artifact embeds that PDF and its button hands it over through the Artifact `downloads` capability. `window.print()` stays as the fallback outside a viewer | Owner 2026-09-03: "ไม่ต้องทำเป็น docx+PDF"; owner 2026-09-04: "ปุ่ม Save to PDF ต้องทำแบบจริงจัง เพราะใน claude artifact กด print ไม่ได้" — the viewer sandbox blocks printing, so the file must exist before publish |
| — | Dated facts carry a Google-owned source | Every claim with a date in the references (retired rich results, llms.txt, Lighthouse categories) cites a `developers.google.com` / `developer.chrome.com` / `blog.google` URL; `validate.py`'s `RETIRED` table is pinned to the reference and rejects other hosts | The 2026-05-07 FAQ retirement went unnoticed in 0.1–0.3; a source per claim makes staleness checkable instead of hoped-for (pattern seen in claude-seo's `google-updates.json`) |
| — | Collector safety | Refuse private / loopback / link-local / metadata targets and redirect targets unless `--allow-private`; sitemap XML capped at 20 MiB and rejected with a DOCTYPE; DNS resolved once per fetch (no pinning — documented limitation) | A skill fetches whatever URL a user or a sitemap hands it; stdlib urllib cannot pin DNS cheaply, the rest is ~80 lines |
| — | FAQPage after 2026-05-07 | Structural AEO signal only (low / info); never a defect, never "add for Google"; `QAPage` for real user Q&A; existing blocks stay if they mirror the page | Google retired FAQ rich results for all sites; the visible answer block is what moves the AEO score |
| — | **DEFERRED** keyed connectors (owner, 2026-09-03) | No script or tool that needs an API key in Phase 1 (PSI / CrUX, Search Console, Bing). PSI's unauthenticated quota is shared and returned 429 on the first probe | Owner: "เน้น lean ที่จบได้ใน plugin ของเราก่อน"; Phase 2 connectors as planned in brief 05 |
| — | Site-type emphasis | Guidance table, not code: detected type with `high` confidence moves its signals one severity step up; `low` / `unknown` keeps default weights | Uses what the collector already detects; keeps scoring explainable and the SKILL short |
| — | hreflang reciprocity | Checked among fetched pages only; Full mode fetches same-origin alternates; Quick mode reports `alternates_not_fetched` rather than guessing | Verify-first: a reciprocity claim needs both pages |
| — | Report design (0.7.0) | The owner's Claude Design mock is the reference: sidebar + dark hero with ring gauges, Instrument Sans + JetBrains Mono, indigo / coral / lime accents, cards with Evidence / Fix panels, matrix cards, roadmap + ongoing card, band cards. Fonts are embedded from `skills/seo-audit/assets/fonts.css` (variable woff2, latin + latin-ext, OFL notice in the file, ~112 KB) so every viewer renders the same; no scripts beyond `window.print()`; CSS values measured from the mock element by element | Owner: "ตอนนี้ดูโบราณเกินไป", then "ช่องว่างและ font ไม่สวยเหมือนตัว design … ให้เหมือนเป๊ะ" — Google Fonts did not load the same everywhere, so the ~112 KB per report buys exactness |
| — | Search Console data without a key (0.10.0) | `seo-fix-plan/scripts/gsc_csv.py` reads the owner's manual Performance export (zip / CSV); **optional** — the audit and the fix plan are complete without it, the skills ask at most once and never block | Owner: keyed connectors stay Phase 2, and "บางคนขี้เกียจ export มาให้ แค่อยาก audit งานที่ live อยู่" — real demand data when it is free, never a gate. Idea from claude-rank's gsc-analyzer |
| — | CI gate | `render_report.py --min-score` exits 1 below a per-dimension minimum; the file is still written | claude-rank's `--threshold`; the owner's SaaS / CI can gate on the sidecar without a second tool |
| — | Page selection (0.11.0 → 0.12.0) | Structure comes from the **sitemap first**: Quick = home + every first-level URL (`/x`) + the two newest second-level pages per section + menu links the sitemap missed (cap 40, reported); no sitemap → navigation markup and the report says so; neither → key-page patterns. Full = Quick + footer + per-section sitemap sample, newest first (10 per section, cap 150); `--all` and `--sitemap-status` opt-in; `--plan` gives the numbers for the mode question, Quick recommended | Owner: nav markup differs per site (anthropic.com read as "menu 3" from nav, 29 first-level sections from the sitemap); URL depth in the site's own sitemap is objective. A 1,000-post blog stays a sample by default |
| — | Release staging | 0.1.0 = `/seo-audit`; 0.2.0 = `/seo-fix-plan` + `/seo-schema` + `/seo-page-brief` (brief planned page-brief for 0.3.0) | page-brief is the content half of the fix-plan hand-off; shipping it with fix-plan avoided a dangling pointer for one release |
